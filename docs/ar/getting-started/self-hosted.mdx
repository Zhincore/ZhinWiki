يسحب مسار الإنتاج الموصى به صورة linux/amd64 مثبتة الإصدار من GHCR
(`ghcr.io/zhincore/zhinwiki`). ولا
يجمع المستودع الأحادي على الخادم. أكمل هذا الدليل التعليمي على مضيف مؤقت قبل
نقل المحتوى الحقيقي.

## المتطلبات المسبقة

جهّز ما يلي:

- مضيف Linux عليه Docker Engine وDocker Compose v2 (`docker compose`)؛
- الأدوات `curl` و`sed` وOpenSSL؛
- اسم مضيف للوحة التحكم واسم مضيف منفصل للتخزين يمكن الوصول إليه من المتصفح؛
- وكيلاً عكسيًا يدعم TLS؛
- بريدًا إلكترونيًا صادرًا عند تفعيل التحقق بالبريد الإلكتروني؛
- سعة منفصلة كافية للنسخ الاحتياطية من Postgres وتخزين الكائنات.

تحقق من الأدوات المطلوبة:

```bash
docker --version
docker compose version
curl --version
openssl version
```

## نزّل ملفات الإصدار

يرفق كل إصدار ملف Compose الخاص بالإنتاج وقالب البيئة. نزّل الملفين إلى مجلد
جديد، واحفظ القالب باسم `.env`:

```bash
mkdir wiki && cd wiki
curl -fsSLO https://github.com/Zhincore/ZhinWiki/releases/latest/download/docker-compose.prod.yml
curl -fsSLo .env https://github.com/Zhincore/ZhinWiki/releases/latest/download/env.production.example
```

الملفان نفسهما هما `docker-compose.prod.yml` و`.env.production.example` في نسخة
محلية من المستودع. يثبّت كلاهما `NIBLEAF_VERSION` على وسم إصداره.

## هيّئ البيئة

عيّن كل قيمة مطلوبة في `.env`. أنشئ أسرارًا مستقلة؛ ولا تُعد استخدام قيم
الأمثلة أو التطوير أو قيم بيئة أخرى مطلقًا:

```bash
openssl rand -hex 32
openssl rand -base64 24
```

ثم اسحب الإصدار المثبت وشغّله:

```bash
docker compose -f docker-compose.prod.yml pull
docker compose -f docker-compose.prod.yml up -d
```

تطبّق خدمة `migrate` ذات التشغيل الواحد عمليات ترحيل Prisma قبل بدء خدمات
التطبيق.

## تحقق من أول نتيجة

شغّل:

```bash
docker compose -f docker-compose.prod.yml ps
docker compose -f docker-compose.prod.yml logs migrate
docker compose -f docker-compose.prod.yml logs --tail=100 server worker app
```

ينبغي أن تكون جميع الخدمات طويلة التشغيل سليمة، وأن تنتهي `migrate` بنجاح.
افتح `$APP_URL/sign-up`، وأنشئ المالك الأول، وارفع صورة واحدة، وانشر مشروعًا من
صفحتين. تحقق من عنوان URL للصورة ومن البحث بعد تسجيل الخروج.

إذا كانت إحدى الخدمات غير سليمة، فلا تُعد إنشاء المنظومة مرارًا. اقرأ أول خطأ
لهذه الخدمة واستخدم [استكشاف الأخطاء وإصلاحها](/ar/self-hosting/troubleshooting).
قبل دعوة الكتّاب، أكمل [إعدادات الإنتاج](/ar/self-hosting/configuration)
و[قائمة التحقق للإنتاج](/ar/self-hosting/production) ونفّذ عملية مجرّبة
لـ[النسخ الاحتياطي والاستعادة](/ar/self-hosting/backups-upgrades).
